# ノートの古い説明と、項目の文に残る内部の番号

## 要旨

- ノートの説明を今の検出の方式に直し、内部の番号が残った項目を演者の帳面に出さないようにした
- 全編の作り直しで、項目の文、弟子役の指摘、ノートのどれからも番号と「音量」が消えた
- 同じ録音の作り直しで、予測の数字が動いた（山のある割合 46% → 33%）。一度の値を成果として書かない
- 判断をお願いしたいことは 1 件（マージの指示）

## 何を狙って、どういう順で作ったか

全編の結果を読むと、説明に「音量」が残り、演者の読む文に内部の番号が出ていた。デモで映ると誤りになるので、画面で答える機能の前に直した。

## 到達点

| 誰が | 何をする | 結果 |
| --- | --- | --- |
| 演者 | ノートを読む | 検出の説明が今の方式になる。「音量」と書いた文は決まった文に置き換わる |
| スクリプト | 文に内部の番号が残る項目を見つける | 保留にして、`.md`、札、ノートの候補から外す。項目は消さない |
| スクリプト | 保留の項目を構成作家役に差し戻す | 文が直れば保留が解ける。直らなければ保留のまま、数が `run.json` に出る |
| 演者 | 画面で保留の項目を見る | 「文に内部の番号が残っている」と理由が分かる |

出力の例（ダミーの高座を headless Chrome で開いた結果。設計どおり、2 種類の保留が別のラベルで出る）：

```
保留（文に内部の番号が残っている）
保留（引用で言えない）
```

## 主な判断と、その理由

| 判断 | 理由 |
| --- | --- |
| 番号の残る項目は落とさず保留にした | 実データで 71 件中 7 件に当たり、サゲも含まれていた。落とすと噺が欠ける |
| 差し戻しをスクリプトが出す | 保留は弟子役に見えないので、弟子役からは差し戻しが来ない。解ける経路が要る |
| 照合で保留の項目には番号の理由を上書きしない | 上書きすると、`knowledge` への書き直しで照合なしに保留が解ける |
| 弟子役の指摘の文は、指示だけで止める | 落とすと指摘が消え、解決の判定も止まる。次の実機の件数を見て決める |
