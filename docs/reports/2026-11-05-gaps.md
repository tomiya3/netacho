# 笑いどころの予測と 3 区分

## 要旨

- 構成作家役が反応を見ずに笑いどころを予測し、スクリプトが AST の笑いと重ねて、的中、空振り、予測なしで反応ありに分けるようにした
- 予測なしで反応ありの笑いは、Claude が演者への問いにする。答えは既存の `netacho answer` で型に残る
- **実機は未実行**。的中率は、ユーザーが実行するまで数字が無い

## 何を狙って、どういう順で作ったか

実機で回収が 4 分の抜粋で 0 件、全編でも 2 件で、見せ場の 1 番が細かった。審査の「Claude の新しい使い方」の決め手として、Claude が読めなかった所を芸の深さとして演者に問う形にする。

## 到達点

| 誰が | 何をする | 結果 |
| --- | --- | --- |
| 構成作家役 | 文字起こしだけで笑いどころを読む | 反応は見ない |
| スクリプト | 予測と笑いを重ねる | 的中、空振り、予測なしで反応あり |
| ノート役 | 読めなかった笑いを問いにする | 反応の全体は見ない。直前の台詞だけ |
| 演者 | `netacho answer` で答える | 言葉のまま型に入る |

## 主な判断と、その理由

| 判断 | 理由 |
| --- | --- |
| 予測は kind `くすぐり` として書く | 回収、根拠の検証、照合、候補の選択をそのまま使える |
| 問いは `questions.json` に入れる | 経路を増やさず、`answer` と画面がそのまま使える |
| 問いは近い笑いを束ねて強い順に 5 件まで、全数は別に数える | 演者に読める量にする。数を上限で隠さない |
| 拍手は比較に使わない | 登場や中手に出るので、笑いどころとは別 |
| 自動の反応が無い高座と、末尾で切れた窓は判定しない | 未検出を空振りと呼ばない |
| 的中率に、窓が覆う割合と、窓に入った笑いの数を添える | 予測が多いと窓が高座の大半を覆い、的中率だけでは過大に読める |
