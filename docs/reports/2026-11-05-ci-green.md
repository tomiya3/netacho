# CI を緑にする（§8 手順 10 の PR）

## 要旨

- main の CI が 2 件落ちていた原因を突き止めて直した。あわせて、Issue から PR までの開発の流れを一度通して確かめた
- 手元では全テストが通る。bash 5.2 と Linux での結果は、この PR の CI で確かめる
- 判断をお願いしたいことは 2 件（マージの指示、API の認証の用意）

## 何を狙って、どういう順で作ったか

T0 のできた条件は「初回 push が済み、CI が緑。手順 10 の PR で、Issue、フック、reviewer、報告書、自動レビューが動いた」。main の CI が赤かったので、手順 10 の「小さな PR」をこの修正に充てた。別の小さな修正を作るより、T0 の 2 つの条件を 1 本で満たせるため。

## 到達点

## 主な判断と、その理由

| 判断 | 理由 |
| --- | --- |
| 手順 10 の PR を CI の修正に充てた | 練習用の変更を作るより、T0 に必要な修正で流れを確かめるほうが早い |
| `/tmp` の読み替えは、`/tmp` が実際にリンクのときだけにした | 最初の修正は Linux 用の回避策を足す形だったが、reviewer の指摘で、読み替えの条件を直すほうが単純で、リンク検査の抜けも一緒に塞がると分かった |
| 置換先を引用符で囲み、シェルの設定は変えなかった | 古い bash（macOS の 3.2）と新しい bash（5.2）のどちらでも意味が同じになる |

## 付録：技術的な記録

- Issue：#1
- 修正前の CI の失敗：run 41860581099
- 原因 1：`pat=${pat//@N@/$N}` の置換先の `&` が、bash 5.2 の `patsub_replacement` で「一致した文字列」に化け、`[^;&|]*` が `&&` をまたいでいた。ケース `git push origin x && git log -d` が ask になった
- 原因 2：`/tmp` → `/private/tmp` の読み替えが Linux でも動き、`git rev-parse` の root（`/tmp/...`）と一致しなかった。`rm -rf <repo>/out/test_c` が ask になった
- reviewer が見つけた別の抜け：Linux では `/tmp/claude-*` の中のリンク検査が効いていなかった（読み替えた先の `/private/tmp` が無いため）。macOS では ask になる `rm -rf /tmp/claude-x/link/foo` が、Linux では素通りした。`[ -L /tmp ]` のときだけ読み替える形で直し、テストを足した
- 自動レビューの指摘 1：`/tmp` が `/private/tmp` 以外へのリンクの環境で判定がずれる。`/tmp` が `/private/tmp` へのリンクのときだけ読み替え、`/private/tmp/claude-*` を一時フォルダとみなすのも同じ条件のときだけにした。これに合わせて `guard_bash_cases.tsv` の 1 行を `/tmp/claude-*` に直し、`/private/tmp` の場合は OS で期待が変わるので別のテストに分けた
- 自動レビューの指摘 2（見送り）：`git push origin x && git log -d` のテストは `guard_bash_cases.tsv` の 56 行目にあり、修正前の CI はこのケースで落ちていた
- 注記：手順 10 の順は「フックの拒否 → reviewer → /report → /pr → 自動レビュー」のとおり。拒否の確認のために、コミットと push は reviewer の前に済ませた
