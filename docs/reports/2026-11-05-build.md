# T4 構成作家役、根拠の検証、照合役、マージ

## 要旨

- `netacho build` で、文字起こしから噺と型を作る流れができた。役の本文、根拠の検証、照合、マージ、`.md` の書き出しまで
- **実機の API はまだ呼んでいない**。テストは偽の client。認証が無いため
- 判断をお願いしたいことは 1 件（API の認証の用意）

## 何を狙って、どういう順で作ったか

見せ場の土台になる「根拠つきの型」を作る。Claude の出力をそのまま正本に入れず、スクリプトの検証と照合役を挟む。審査の「Claude の活用」で見せる「見せる物の境界で分けた役」と「落とした件数」はここから出る。

## 到達点

| 誰が | 何をする | 結果 |
| --- | --- | --- |
| 構成作家役 | 文字起こしから噺と型を抜き出す | 反応は見ない。時刻と引用は書けない |
| スクリプト | 区間と kind の約束に照らす | 落とした項目を理由ごとに数える |
| 照合役 | 項目の文が引用で言えるかを判定する | 演目名も文字起こしの全体も見ない |
| スクリプト | 正本に入れる | 演者の項目は変わらない。id も変わらない。言えない項目は保留で `.md` に出ない |

## 主な判断と、その理由

| 判断 | 理由 |
| --- | --- |
| 照合役に渡すのは `heard` の項目だけ | `knowledge` は録音に根拠が無いのが定義で、渡すと全部 unsupported になる。暫定と表示し、数だけ残す |
| 判定が返らなかった項目は保留 | 確かめていない物を通さない |
| `.md` に録音の引用を出さない | 弟子役は `.md` だけを読む。引用があると書かれていない物を補えてしまい、「読めない所が伝承の抜けになる」ねらいが弱くなる |
| 間の根拠の下限を 0.5 秒にそろえた | 役に見せる下限と検証の下限が違うと、見せた間で書いた項目が必ず落ちる |
| 根拠の長さの上限（3 分）を役の本文にも書いた | 黙って全滅するのを防ぐ |
| 同じ噺の同じ場面は、別の高座でも同じ場面 ID | 場面は噺の単位。区間との対応は高座ごとの timeline が持つ |
