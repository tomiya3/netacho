# 画面から録音を入れる（#62）

## 意図
演者が端末を使わずに済むようにする。`netacho serve` を起動したら、あとはブラウザの中で、録音を入れ、進み具合を見て、できた高座を開き、問いに答えられる。

## 判断
- 処理は段階ごとに別のプロセスで `python -m netacho` を回す。端末で打つのと同じ道なので、`budget.py` の上限、`--reuse` のやり直し、run.json の実測がそのまま効く
- 段階：鍵の確認 → prep → build → note → seisho。比べる相手を選んだら compare を足す。鍵の確認を最初に置いて、長い文字起こしの後で落ちないようにした（`netacho auth` を足した。課金なし）
- 同時に 1 本だけ。録音を受け取る前に枠を取り、受け取り中に 2 本目を受けない
- 1 回 $5 の上限は、録音 1 本（やり直しも含む）で数える。段階は別のプロセスなので、始めたときの累計を環境変数で渡す（自動レビューの指摘）
- ディスクに録音の 2 倍と 1 GB の空きが無ければ受け取らない（自動レビューの指摘）
- 状態はサーバのメモリに持つ。画面を閉じても続き、開き直すと見える。サーバを止めると消える（下の依頼）
- 応答に出すのは段階の名前と終了コードだけ。各段階の出力は高座のフォルダの `job.log` にだけ書く。鍵は有無だけを画面に出す
- 大きな録音を送り始めてから断ると理由が届かないので、画面は本文の無い確認（`check=1`）を先に呼ぶ
- 高座が 1 本も無ければ、高座を開かずに起動して、録音を入れる画面だけを出す。作りかけの高座しか無いときも同じ
- 開いている高座は勝手に変えない。できたら「できた高座を開く」を押す（別のタブで答えている途中の書き込みを壊さないため）

## 数字
- `make test` 1008 件、すべて通過。テストは偽のコマンドで回し、API も Whisper も呼ばない
- ダミーの一式と偽の処理で、ブラウザを実際に操作した：空の起動 → 入力 → 進み具合 → 開き直し → 失敗 → やり直し → 完了
- 本物の `netacho serve` で、鍵の無い状態で録音を入れ、「鍵の確認」で止まり、`job.log` にだけ理由が出ることを確かめた
- 実際の録音で最後まで通すのは、鍵のある環境でまだやっていない（この報告書を書いた時点）
- 追記（2026-11-08）：作者が鍵のある手元の環境で、実際の録音を画面から入れ、最後まで通した

## 依頼
- 鍵のある端末で、短い録音を 1 本、画面から最後まで通してください（費用は README の「数字」の表を参照。録音 1 本で $5 を超えそうなら止まります）
- サーバを再起動すると、止まった処理のやり直しの手は画面から消えます。そのときは端末で build、note、seisho に `--reuse` を付けて続きを回します（画面にもそう出します）

## 付録
- 新しい入口：`POST /api/upload`（application/octet-stream、2 GB まで、`.part` に書いてから置き換え）、`POST /api/retry`、`GET /api/job`。どれもトークン、Host、Origin を確かめる
- 演目と会場はフォルダの名前になる。空白、区切り、先頭の `.` と `-` を許さない。語は `--terms=値` の形で渡し、`-` で始まっても引数と取り違えない
- 文脈なしレビュー：中 4、低 4。反映 6。見送り 2：読み取りの timeout は `Handler.timeout`（読み取りごと 10 秒）が既に効いている。状態とスレッドの隙間は、押したときに 409 と理由が出るので許容
