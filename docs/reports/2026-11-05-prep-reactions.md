# T3 前処理と反応の候補

## 要旨

- `netacho prep` で、一席の音声から文字起こしと反応の候補が出るようになった。実際の音声の 5 分の抜粋で動いた
- 反応の候補が本物の笑いかどうかは未確認で、耳での確認が要る
- 判断をお願いしたいことは 2 件（耳での確認、API の認証）

## 何を狙って、どういう順で作ったか

見せ場の 1 番「反応の波と、反応候補が少ない所」の土台。木曜のうちに抜粋で一巡するため、文字起こしと反応の検出を先に通した。

## 到達点

| 誰が | 何をする | 結果 |
| --- | --- | --- |
| ユーザー | 録音と演目名を渡して `netacho prep` | 文字起こし、反応の候補、波が演者のデータの置き場に出る |
| ユーザー | `netacho top` | 強い順の時刻の一覧が出る。耳で確かめる |
| ユーザー | 耳で付けた時刻を `netacho mark` で入れる | 手で付けた反応に置き換わる。自動の結果は別に残る |
| スクリプト | 候補が 0 件のとき | 「反応なしとは限らない」と出す |

## 主な判断と、その理由

| 判断 | 理由 |
| --- | --- |
| 隙間をつないでから長さで落とす | 笑いの波は切れ切れになる。先に長さで落とすと、0.2 秒ずつの笑いが全部消える |
| 強さは「基準を超えた dB の積分」の順位 | plan に定義が無い。音量と長さの両方を見るため。長い反応が有利になるので耳で確かめる |
| 手で付けた反応がある高座の `prep` のやり直しは止める | 耳で付けた結果を黙って消さない |
| `prep` の開始時に古い生成物を消し、`koza.json` を最後に書く | 途中で落ちたとき、新しい音声に古い結果が並ぶのを防ぐ |

## 判断・用意をお願いしたいこと

1. **耳での確認**：次のコマンドの上位 10 件が笑いかどうかを聞いてほしい。結果で閾値を調整する。読めなければ `netacho mark` に切り替える。

   ```
   uv run netacho top --koza 0000-00-00-excerpt
   ```

   時刻は抜粋の先頭からの秒で、元の音声の 5 分 00 秒が 0:00 になる。高座 ID の `0000-00-00` は仮の日付。

2. **`ANTHROPIC_API_KEY` の用意**：この環境には API の認証が無い。T4 以降の実測に要る。`.env` は使わず環境変数で。

## リスク

| リスク | 現状 | 対策 |
| --- | --- | --- |
| 10 秒を超えて続く笑いを拾えない | 基準の前後 10 秒の中央値が持ち上がる。合成の音で確かめた（8 秒は拾う、16 秒は拾わない） | 耳で確かめる。起きていれば基準の取り方を変えるか `netacho mark` で補う |
| 台詞の強い所が候補に混ざる | 未確認 | 耳で確かめて閾値を調整する |
| 候補の良し悪しを合成の音でしか確かめていない | テストは近似 | 耳での確認が本番 |
