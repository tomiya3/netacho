# T5 「薄い」候補とノート役

## 要旨

- `netacho note` で、回収と反応から候補をスクリプトが選び、ノート役が短い文にして `note.md` を書くようになった
- **実機の API は未実行**。候補の良し悪しは、反応を耳で確かめるまで判断できない
- 判断をお願いしたいことは 1 件（反応の耳での確認。#7 の報告書と同じ）

## 何を狙って、どういう順で作ったか

見せ場の 1 番「ここは仕込みがあるのに反応候補が少ない」を作る。選ぶのはスクリプト、文にするのが Claude、決めるのは演者。

## 到達点

| 誰が | 何をする | 結果 |
| --- | --- | --- |
| スクリプト | 回収の後 6 秒の窓を見て候補を選ぶ | 窓に候補が無い、または高座の回収の中で下位 4 分の 1 |
| ノート役 | 選ばれた候補を演者向けの文にする | 反応の全体も型の全文も見ない |
| スクリプト | 文を検査する | 断定、客の気持ち、提案、数字、3 文以上は決まった文に置き換えて数える |
| 演者 | `note.md` を読む | 文と、仕込みと回収の引用が見える。原音で確かめられる |

## 主な判断と、その理由

| 判断 | 理由 |
| --- | --- |
| 自動の反応が 1 件も無い高座では `no_candidate` を出さない | 手の印は聞いた所だけ。拾えなかった高座で全回収を「候補が少ない」と呼ばない（plan の「未検出を反応なしと扱わない」） |
| 録音の末尾で窓が切れて候補が無いときは判定しない | 録音が足りないだけかもしれない |
| 順位のある回収が 4 件未満なら `low_rank` を出さない | 少ない中で 4 分の 1 は言えない。強い回収を無理に薄いと呼ばない |
| ノート役の文は検査して、崩れたら決まった文に置き換える | 役の出力で断定が演者に届くのを防ぐ。再試行はしない |
